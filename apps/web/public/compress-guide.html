🎬 视频压缩教程

上传到网站前先压一版：又快又清晰，观众打开/拖动也更流畅

一句话结论：把 4K/超高码率原片（常 500MB–2GB）压成 H.264 + ≤1080p + 2~3Mbps 的网页版，讲课/PPT 画面肉眼几乎无差； 800MB 级原片通常可压到 200–400MB。原片留档，网站传压缩版。

推荐参数

项建议值原因
编码H.264浏览器兼容最好，免二次转码
分辨率≤1080p（竖屏 1080×1920）够清晰、体积小一半以上
码率2–3 Mbps（活动记录可 4M）讲课/板书/PPT 足够
帧率25 或 30与素材一致即可
音频AAC 128k 立体声质量与体积平衡
画质档≈ CRF 20–23恒定质量、观感几乎无损

用 ffmpeg（一条命令）

ffmpeg -i input.mp4 -c:v libx264 -preset medium -crf 22 \
  -maxrate 3M -bufsize 6M -vf "scale='min(1920,iw)':-2" \
  -c:a aac -b:a 128k -movflags +faststart output.mp4
💡 想控制更准的体积，可把 -crf 22 换成 -b:v 2.5M -maxrate 2.5M -bufsize 5M。Mac 自带 ffmpeg？没有就装 Homebrew：brew install ffmpeg。

不用命令行（图形工具）

• 剪映（免费）：导出 → 自定义 → 分辨率 1080p、码率“中/较高(≈3Mbps)”、H.264、MP4

• 格式工厂 / HandBrake（免费）：预设选 H.264 + MP4 + 1080p，质量 CRF 20–22

• 手机拍摄：iPhone 可开“高效(HEVC)”，但传到网站前仍建议转 H.264 MP4；MOV 兼容性差勿直传

体积速查（2.5Mbps 视频 + 128k 音频 ≈ 0.33MB/秒）

时长预计体积
5 分钟≈ 95–110 MB
10 分钟≈ 190–220 MB
30 分钟≈ 550–650 MB（建议拆 2–3 集，单集 ≤300MB）

大文件（>90MB）直接传也可以

网站已支持 分片直传 R2：64MB/片、3 路并发，浏览器直接 PUT 到存储端点， 不再受 100MB 限制；上传弹窗会显示百分比与“第 x/N 片”。仍建议先压缩一版——省存储、观众体验更好。
